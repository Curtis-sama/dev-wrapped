# Put the Git Wrapped card on a GitHub profile

Goal: the user's profile (`https://github.com/<login>`) shows an animated card generated by the
`Curtis-sama/dev-wrapped@v1` GitHub Action, refreshed every day.

It takes three things in the user's **profile repository** (the public repo named exactly like their
username, `<login>/<login>`):

1. a workflow at `.github/workflows/dev-wrapped.yml`
2. the line `![My Git Wrapped](./dev-wrapped.svg)` in `README.md`
3. one manual run of the workflow, which commits `dev-wrapped.svg`

Work through the steps below in order. Tell the user what you are about to do before each step that
creates or changes something on GitHub, and wait for their go-ahead.

## 1. Check the GitHub CLI

```bash
gh auth status
```

If `gh` is missing or not logged in, ask the user to install it (https://cli.github.com) and run
`gh auth login`, then continue. If pushing fails later with a `workflow` scope error, ask them to run
`gh auth refresh -s workflow`.

Get the login:

```bash
gh api user -q .login
```

## 2. Make sure the profile repository exists

```bash
gh repo view <login>/<login> --json name,visibility,isEmpty
```

- **Not found**: ask the user, then create it:
  ```bash
  gh repo create <login> --public --add-readme --description "My GitHub profile"
  ```
- **Private**: tell the user that GitHub only shows a profile README from a **public** repository and
  ask whether to make it public (`gh repo edit <login>/<login> --visibility public --accept-visibility-change-consequences`).
- **Empty**: it has no README yet; you will create one in step 4.

Clone it into a temporary folder and work there:

```bash
gh repo clone <login>/<login> /tmp/<login>-profile
```

## 3. Add the workflow

Detect the user's time zone so coding hours are accurate:

```bash
node -e "console.log(Intl.DateTimeFormat().resolvedOptions().timeZone)"
```

Confirm it with the user, then write `.github/workflows/dev-wrapped.yml` (replace `<TIMEZONE>`):

```yaml
name: Git Wrapped
on:
  schedule:
    - cron: '0 6 * * *'
  workflow_dispatch:
  push:
    paths: ['.github/workflows/dev-wrapped.yml']
permissions:
  contents: write
jobs:
  card:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: Curtis-sama/dev-wrapped@v1
        with:
          timezone: <TIMEZONE>
```

If the file already exists, show the user the differences before replacing it.

## 4. Add the card to the README

Insert this line in `README.md`:

```markdown
![My Git Wrapped](./dev-wrapped.svg)
```

Rules:

- If the line (or `dev-wrapped.svg`) is already there, do not add it twice.
- **Never put it inside an HTML comment** (`<!-- ... -->`). GitHub's default profile README wraps
  most of its content in a comment: insert the line right after the first heading, before any `<!--`.
- If there is no README, create one:
  ```markdown
  ## Hi there 👋

  ![My Git Wrapped](./dev-wrapped.svg)
  ```

Show the user the top of the updated README before committing.

## 5. Commit and push

```bash
cd /tmp/<login>-profile
git add .github/workflows/dev-wrapped.yml README.md
git commit -m "Add Git Wrapped card"
git push
```

## 6. Generate the card

Pushing the workflow file starts the first run by itself (`push` trigger). Wait a few seconds, then
find it:

```bash
gh run list -R <login>/<login> --workflow dev-wrapped.yml --limit 1
```

If no run shows up after ~30 seconds (for example the workflow file already existed and did not
change), start one by hand:

```bash
gh workflow run dev-wrapped.yml -R <login>/<login>
```

Then follow the run:

```bash
gh run list -R <login>/<login> --workflow dev-wrapped.yml --limit 1
gh run watch -R <login>/<login> <run-id> --exit-status
```

Check that the card was committed:

```bash
gh api repos/<login>/<login>/contents/dev-wrapped.svg -q .name
```

## 7. Report

Tell the user it is done and give them `https://github.com/<login>`. Mention that:

- the card refreshes every day at 06:00 UTC, and they can run it by hand from the **Actions** tab
  (**Git Wrapped → Run workflow**);
- it follows each visitor's light or dark theme.

## Optional: include private contributions

The default workflow token only sees **public** activity. If the user works in private repositories
and wants them counted:

1. Ask them to create a classic token at https://github.com/settings/tokens/new with the `repo` and
   `read:user` scopes. **Never ask them to paste the token in the chat.**
2. Let them store it themselves, so it never passes through the conversation:
   ```bash
   gh secret set GH_PAT -R <login>/<login>
   ```
   (`gh` prompts for the value.)
3. Add `github_token: ${{ secrets.GH_PAT }}` under `with:` in the workflow, commit, push, and run the
   workflow again.

## Troubleshooting

| Symptom | Fix |
|---|---|
| Run fails on `git push` with 403 | The workflow needs `permissions: contents: write` (already in the template). Also check **Settings → Actions → General → Workflow permissions** is not restricted to read-only. |
| "Actions are disabled" | Enable them in **Settings → Actions → General**. |
| Card shows few commits | Only public activity is visible: see the private contributions section. |
| Image shows as broken | The workflow has not run yet, or the README line points to a different file name. |
